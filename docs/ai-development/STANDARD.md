# やまだや自律開発原則 v0.1 — mizu パイロット用抜粋
2026-10-18 / 試験導入・正式全社配布前
このファイルは mizu に必要な共通の不変条件を抜粋したもの。会社横断の正本候補は非公開の `yuki2900221/superyamadaya` PR #1 に置かれているが、そのリポジトリをAIが読めると仮定しない。

## やりたい開発方式
- 人間は目的・必須条件・禁止事項を伝える。AIは不足部分の設計、技術選定、実装、テスト、改善を担当する。
- 最初にすべての詳細を質問しない。曖昧なUI・機能は合理的に具体化して実装し、体験評価後に改善できるようにする。
- 小さな個人アプリと、現金・個人情報・給与・店舗運用が関係する本番業務を同じ承認基準にしない。
- Cloudflare・Vercel・Supabase・AWS等の特定サービスを強制しない。既存技術、コスト、セキュリティ、保守、統合可能性を比較する。

## 常に守る境界
1. 秘密値・個人情報・本番データの露出を防ぐ。本番データは無断で操作しない。
2. 本番、外部公開、追加課金、ユーザー権限・認証境界の変更には、影響範囲に対する明示的な許可が必要。
3. 他人・他店舗・他会社のデータを操作できないようサーバー側で認可し、拒否テストも行う。
4. 技術的に安全を保証したい事項は、AI指示に加えテスト、CI、ブランチ保護、認証設定で強制する。
5. 未実施テストは未実施と報告する。検証記録と実際の成功は区別する。

## 内部で確認する12観点
目的/利用者、成功、範囲、正常・例外フロー、予算/期間、承認者、技術/代案、データ/正本/連携、品質/安全、テスト/合格、運用/復旧、リスク/未決。リスクが低ければユーザーに逐一質問せず進行する。

## mizu固有の注意
ゲストのローカル保存、Googleサインイン、D1同期、Workers AIによるタスク分解、オフライン再起動は重要なUX・データ境界。既存の `README.md` と `docs/TESTING.md` を確認し、変更箇所に必要な回帰試験を追加する。
`/goal` はツールに対応し、ユーザーが目標を指定したときにそのスレッドの達成条件として利用する。暗黙の無限実行や本番の無断公開の根拠にはしない。
